# 模型能力优化复验与交付结论

## 结论

继续训练的三个候选（`lora_1p7b_v1`、`v2`、`v3`）均未通过各自**训练前写定**的替换门槛。当前交付仍为 `train/outputs/lora_1p7b_v0/best`，本地 API 加载的也是该适配器。没有把验证损失降低或局部题型进步写成最终模型全面提升。

与此同时，补做了三份训练前冻结的验收集，扩大了对当前交付模型的证据。所有成绩都用模型原始 JSON 输出评分；服务端闸门阻止危险执行，但不给模型本身加分。

| 验收集 | 1.7B 原模型 | 当前交付 1.7B LoRA | 说明 |
| --- | ---: | ---: | --- |
| v1，24 题 | 12/24 | **18/24** | 最早的独立验收 |
| v2b，48 题 | 20/48 | **31/48** | 扩充题型；13 题由错变对、2 题由对变错；另有 1 题待人工复核，未计入正确 |
| v3，32 题 | 13/32 | **19/32** | 增加缺参与越权题 |
| v4，24 题 | 10/24 | **16/24** | 集中考察越权与安全边界 |

`acceptance_v2` 初稿因与旧测试集有 1 条请求完全重复而作废；实际使用 `acceptance_v2b`，与已有数据的最高请求双字相似度约 0.679，低于项目 0.78 的近重复警戒线。v3、v4 分别在对应训练前冻结。v3、v4 是定向压力测试，不能把四份题简单合并成线上准确率。

训练及选择规则分别见 [`qwen3_1p7b_v1_plan.md`](qwen3_1p7b_v1_plan.md)、[`qwen3_1p7b_v2_plan.md`](qwen3_1p7b_v2_plan.md)、[`qwen3_1p7b_v3_plan.md`](qwen3_1p7b_v3_plan.md)。各模型有配置、运行清单、逐轮训练/验证损失、适配器和逐题评分。后续候选的验证损失下降与独立验收成绩不一致，说明仅看 loss 无法判断工具决策是否改善。

## 尚未解决的问题

- 当前交付在 v2b 已知工具缺参为 9/16，未见工具缺参为 1/6；v3 分别为 5/12 和 1/3。未见工具参数缺失仍是明确弱项。
- v4 越权拒绝为 6/8。训练 v3 后反而降到 4/8；部分请求仍被模型错误生成为工具调用。服务端会拦截未经确认的日历写入，但不能据此声称模型会可靠拒绝越权请求。
- 评分器对拒绝理由和中文文本参数使用预设词表；合法改写可能被记为 `wrong` 或 `manual_review`。逐题原文保留，不能事后修改口径来抬高同一批结果。

因此，**可支持的简历结论**是“完成真实 LoRA 训练并在同基座对照中获得可复核提升”，而不是“已把所有中文工具调用场景优化到可靠水平”。下一轮若继续提高模型能力，应扩大人工标注的缺参/越权训练集，同时建立更大、来源独立的真实请求保留集；在新证据出现前不替换当前适配器。
