# 最终项目交付：中文工具调用模型微调与安全推理系统

## 交付范围与结论

保留六个真实服务工具及缺参、越权场景。交付由三层组成：Qwen3-1.7B LoRA 生成候选决策；保守的服务端决策策略只把明确缺参或越权请求改为追问/拒绝；执行闸门验证 JSON Schema、工具范围、参数和日历写入确认。**规则层不会生成工具调用，也不能确认写入。** 未见工具只在离线泛化评测中使用，不在本地 API 的六工具白名单内。

本次权重仍为验证损失选出的 `train/outputs/lora_1p7b_v0/best`。后续三轮补充训练没有同时改善能力与安全，失败证据保留在[优化复验](model_optimization_followup.md)。最终提升来自训练后的模型与服务端策略的组合，不能归功于再次微调。

剩余两题：一题完整的未来空闲查询被模型错误当成过去时间拒绝；一题未见工具的缺参换算没有触发保守规则，模型错误拒绝。没有依据这两题改规则后重测同一冻结集。公开仓库保留 [`acceptance_v5b_final_pipeline/`](acceptance_v5b_final_pipeline/) 的系统评分汇总，以及 [`acceptance_v5b_qwen1p7b_base/`](acceptance_v5b_qwen1p7b_base/) 与 [`acceptance_v5b_qwen1p7b_lora_raw/`](acceptance_v5b_qwen1p7b_lora_raw/) 的模型评分汇总；逐题原始输出留在本地实验目录。

## 工程实现与复核

- 微调：PyTorch + Transformers + PEFT/LoRA，训练 408 条、验证 96 条，仅约 160 万参数（0.093%）参与更新；最佳轮次依验证损失选取。训练配置见 [`../configs/lora_1p7b_v0.json`](../configs/lora_1p7b_v0.json)，逐轮损失与哈希见 [`qwen3_1p7b_training_metrics.json`](qwen3_1p7b_training_metrics.json)。适配器权重不随仓库发布。
- 决策策略：[`../api/decision_policy.py`](../api/decision_policy.py) 对跳过确认、记录修改、已知不支持操作及必填字段缺失做保守拦截；仅可返回 `clarify`/`refuse`。未命中规则时沿用模型原始建议。
- 执行边界：[`../tools/executor.py`](../tools/executor.py) 复用工具 Schema、工具白名单和服务端可信上下文；日历写入需要一次性确认令牌。
- 中文页面同时展示模型原始建议、最终系统决策和执行闸门结果，避免把两者混淆。
- 交付前执行测试集冻结校验、8 项规则单元测试和 6 项真实模型 API 集成测试，均通过；本地服务健康检查返回 `Qwen3-1.7B` 与适配器哈希。

## 如何表述能力

可以说：“在同一 Qwen3-1.7B 基座上进行 LoRA 微调，最终独立 48 题中原模型 25/48、LoRA 原始输出 32/48；结合只降级为追问/拒绝的服务端策略后，系统决策达到 46/48，缺参 14/14、越权 10/10。”

不能说“LoRA 训练把正确数从 25 提升到 46”或“任意真实请求准确率 95.8%”。验收集是有限的合成请求，规则覆盖之外仍可能失败；服务端闸门负责最终执行安全，模型和规则都不等于生产级安全保证。
