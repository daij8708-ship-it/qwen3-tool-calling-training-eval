# 五路 Agent 第一层路由验证

## 目标与边界

本地 Qwen3-1.7B + LoRA 只选 `technical`、`realtime`、`service`、`ticket`、`general` 之一。实际回答和业务工具交给 ITS 多智能体项目的云端 Agent。遇到多任务、无法解析、未知工具或本地服务不可用时，交给原有云端主调度。服务端对结果做白名单校验，不执行模型输出的工具调用。

## 训练

在已有六工具 LoRA 最佳适配器上继续训练新的路由适配器，不改动原适配器。五路各有 24 条训练种子，共 120 条，扩展为 240 条训练样本；验证集 25 条。仅答案 token 计损失，AdamW 学习率 `5e-5`，梯度累积 8，2 轮，以验证损失选最佳轮次。第 1 / 2 轮验证损失为 `0.000522` / `0.000279`；第 2 轮适配器用于下面的评测。新适配器 SHA-256：`5dacf225a2aac4abf52e566c05a6714ff0cfe230dd99492db8449259d54dd2a6`。

## 结果

| 数据 | 结果 | 用途与解释 |
| --- | ---: | --- |
| 训练后首次运行未见的 30 条题 | 29/30 | 五个单路由各 5/5，多任务 4/5；这组的首次成绩是主要的独立验证证据 |
| 修正多任务回退词后重跑同一 30 条题 | 30/30 | 回归结果；曾针对其中 1 条失败样例调整规则，不能视为新的独立测试 |
| 多智能体项目原有 20 条场景 | 20/20 | 接入回归；其中 16 条单任务，4 条多任务；调试时参考过这些场景 |

首轮未见题的单路由结果是 `25/25`；这说明该小规模定向集中的五路分诊有效，但不能推导真实流量准确率。多任务使用服务端保守回退规则；这部分分数不能算作纯模型能力。逐题预测保存在本地 `reports/agent_route_*/predictions.jsonl`，公开仓库保留样例及评分汇总。

## 真实链路

通过 `/route` 选中技术 Agent，云端技术 Agent 成功调用 8001 知识库的 `query_knowledge`，返回包含文档来源的排障答案；结束包记录路由 `technical`。普通对话 Agent 也完成过真实云端回答。多智能体项目新增 3 项接入测试通过，原有 12 项路由契约测试通过。模型项目的 11 项路由与策略测试通过。知识库在验证时临时启动，验证后已停止；日常运行按多智能体项目的启动方式启动知识库。

## 复现

先按根目录 README 准备 Qwen3-1.7B 和原六工具 LoRA，再运行 `train/train_agent_router.py`。启动本项目 API 时使用 8011；多智能体知识库使用 8001。运行 `eval/agent_route_eval.py` 可对任意同格式 JSON 样例逐题评分。公开仓库不提供模型权重，因此仅凭源码无法复现模型数值，需本地训练或提供相同适配器。
