# 第一层路由配对评测（2026-10-05）

## 结论

在同一批 80 条冻结任务上，原云端编排器完成 80/80 条正确路由。本地 Qwen3-1.7B LoRA v2 对 60 条单智能体任务选对 59 条（98.33%），对 20 条跨智能体任务全部正确识别并交回云端编排（20/20）。按照当前混合架构的路由策略计，本地为 79/80（98.75%）。因此，本轮不能宣称本地路由准确率超过云端。

唯一错误是 P074：“先查本周手机行业消息，再查本周芯片行业消息。”两个步骤都属于 `realtime`，本地却返回 `model_multi_task`，触发了不必要的云端回退。它不会直接路由到错误的专业智能体，但会增加一次本地判断和后续云端调用。

## 测试口径

- 题库：[router_pairwise_v3.json](../data/agent_route_pairwise_v3.json)，SHA-256：`661e77eb129efd67b7a58eff64632de5560bb3d8036fe4043d32633936a1b94e`。80 条任务含五类单智能体任务各 10 条、跨智能体任务 20 条、同一智能体的多步骤任务 10 条。与此前的训练种子、冻结集和 80 条 holdout 无完全相同题目。
- 云端侧沿用 ITS 项目现有第一层编排器的提示词、模型、温度和五个专家工具的名称、描述、参数结构。五个工具的执行体换成仅记录调用的空实现，因此不运行专业智能体、MCP 或业务工具。跨智能体任务要求云端选出完整的预期智能体集合。
- 本地侧直接调用已接入 ITS 的 `/route` 服务。单智能体任务要求精确选中预期智能体；跨智能体任务要求返回 `model_multi_task`，由现有云端编排器继续处理。本地没有在一次请求中列出两个智能体的能力，因此 20/20 表示“正确识别并回退”，不是“双路由全选对”。
- 两侧按同一题库逐题运行一次；没有根据这批结果改题、调参或重新训练。评分只看第一层路由决策，不包含下游任务执行成功率。

## 结果

| 指标 | 云端编排器 | 本地模型 + 回退策略 |
| --- | ---: | ---: |
| 单智能体精确路由 | 60/60 | 59/60 |
| 其中五类直接单智能体请求 | 50/50 | 50/50 |
| 同一智能体多步骤请求 | 10/10 | 9/10 |
| 跨智能体请求 | 20/20 选出完整集合 | 20/20 识别并回退 |
| 按各自架构策略的总正确数 | 80/80 | 79/80 |
| 单智能体路由耗时 P50 / P95 | 1756 / 2841 ms | 1031 / 1238 ms |
| 跨智能体决策耗时 P50 / P95 | 1874 / 2554 ms | 388 / 405 ms，仅本地回退判断 |

耗时是本次串行测试的观察值，不是并发服务压测。云端跨智能体耗时包括它调用空实现工具后继续编排的时间；本地跨智能体耗时只计算回退判断，后续云端编排耗时不在其中，不能据此声称整条任务链更快。本地运行的设备开销和云端调用价格也未纳入成本核算。

云端空实现编排器共发出 160 次模型请求，计 505,712 tokens。这是该模拟口径下的观察值，不能直接当作真实业务成本或混合架构节省量。
